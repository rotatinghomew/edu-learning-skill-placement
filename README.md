# 评分者尺度差异下的学习成果与志愿岗位匹配

这是一个面向社区老年教育运营的本地分析原型：把课堂作品评分、课程档案、
志愿岗位与排班记录放在同一份可追溯档案里，演示如何从原始评分得出
**可比较但带不确定性**的能力证据，再据此给出岗位推荐。所有记录均为本地
合成数据，不包含个人信息。

## 环境与使用

需要 Python 3.11 或更高版本，无第三方依赖。

```bash
python3 -m unittest discover -s tests -v   # 运行测试
python3 -m learning_skill_placement.report # 查看合成档案的运营摘要
```

也可使用 Docker（镜像固定在 docker 官方 python:3.11-slim 摘要上）：

```bash
docker build -t learning-skill-placement .
docker run --rm learning-skill-placement
docker run --rm --entrypoint python3 learning-skill-placement -m unittest discover -s tests -v
```

`report` 默认只读 `data/*.csv`，SQLite 数据库写入临时目录后立即丢弃；
用 `--database 路径` 可以保留数据库，用 `--data 目录` 可以指向另一份档案。

## 档案结构

`data/` 下的 CSV 构成完整档案，读取时做引用完整性与时间顺序校验：

| 文件 | 内容 |
| --- | --- |
| `skills.csv` | 技能维度 |
| `students.csv` | 学员与所属社区 |
| `works.csv` | 作品、作者、提交时间 |
| `ratings.csv` | 评分：作品、技能维度、评分者、分数、评分时间、`replaces_rating_id` |
| `vacancies.csv` | 岗位、必要技能与要求水平（logit 尺度） |
| `sessions.csv` | 服务时段、独立/带教席位、默认带教者 |
| `mentors.csv` | 带教者与同时带教容量 |
| `registrations.csv` | 报名：状态 `requested`/`confirmed`/`withdrawn`、方式、带教者 |
| `decisions.csv` | 已做出的资格决定、理由与当时引用的评分编号 |

重评是**另一条判断**，不是另一份作品：新的评分记录指向同一作品、同一技能，
用 `replaces_rating_id` 指回被替换的旧评分。档案里可以同时查到旧依据和新证据，
但同一评分者对同一作品同一技能的现行判断只能有一条。

## 能力证据的口径

`network.py` 把每条现行评分写成

```
logit(分数) = 学员能力 θ − 评分者尺度 b + 误差
```

并**只在同一技能、且通过共同作品或共同评分者实际连接的评分组内**估计。
同名技能下互不连通的评分组各自定锚、各自给出组内名次，绝不拼成一张总榜。
评分组只有一位评分者或一位学员时，学员能力与尺度不可分离，该组只能输出
“不确定”。

每个可比评分组同时给出方差分解：学员能力、作品差异、评分者尺度、残余判断
各解释多少评分变异；`analysis.py` 还并排列出原始平均分与调整后能力，
便于看出“换了老师后突然进步”其实是尺度差异。

## 资格、不确定性与重评

`qualification.py` 对每个岗位的每项必要技能给出 `met` / `not_met` /
`uncertain`。缺评、评分组尺度不可分离、证据条数或作品数不足、置信区间
跨过要求水平，都传递成 `uncertain`，既不默认低分，也不默认合格。
资格结论附有评分编号与来源（作品、评分者、分数、时间、是否现行），
可由档案复算；历史决定只作为既成事实展示，不作为独立真值。

已确定报名不因后续重评被自动撤销：它继续占席位、保留原决定与理由，
同时单独列出“若按现行评分重算”的结果。新的推荐只使用现行评分，
被替换的旧评分不会再次进入估算。

## 岗位推荐与带教负荷

`placement.py` 对每条**待审核**报名给出：

* `independent`：证据达到要求且该时段独立席位有空。
* `supervised`：占用时段带教席位或某带教者的带教名额。
* `pending`：证据不确定/未达要求、学员时间冲突、席位或带教容量不足，
  逐条列出原因。

带教容量按**同时发生**的服务合并核算，既受时段带教席位限制，也受带教者
跨时段的同时带教人数限制，不会超卖。已确定报名先占容量且不被重新分配。
摘要同时给出各岗位的容量、已确定、独立、带教、暂缓与空余，以及带教者的
同时峰值和剩余名额，便于比较岗位覆盖与带教负担；在证据不确定时不会为了
排满班次而给出独立上岗承诺。

## 测试

`tests/test_workflow.py` 覆盖：档案校验、重评关系、尺度扣除、连通分量
不合并、单评分者组的尺度不可分离、证据不足的不确定性、旧资格保留与
新推荐不使用旧证据、独立/带教/暂缓的分类、带教容量跨重叠时段核算、
SQLite 往返与报告渲染。

## 当前局限

* 模型只有学员与评分者两个加性效应，作品差异通过组内残差份额体现；
  不估计任务难度或评分漂移。
* 标准误是基于组内残差与评分条数的近似值，不是完整贝叶斯后验。
* 档案规模与岗位数量按小社区示例设计；调度是逐条贪心分配，不是全局最优。
